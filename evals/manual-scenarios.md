# Agent 真实任务评估

状态：以下端到端场景尚未执行。包内 Python 测试与实际工程扫描只证明工具行为，不证明 Agent 的设计表现改善。

复用现有测试项目或隔离副本，给 Agent 任务文本和必要文件即可。先不提供本文件的观察标准，完成后再对照；若使用独立评估者，遵循当前环境的授权与工具条件。不要擅自影响生产页面。截图应保留视口、主题与内容状态；记录实际命令、选型理由、改动与限制。

## 1. 已有后台的局部打磨

**任务**：“用 $ui-sift 打磨订单列表，让筛选和空状态更顺手。保留现有 Radix、图标与 API，不新增依赖。”

**最小环境**：React 列表，已有日期范围选择，长订单标题，模拟加载失败与无结果。

**观察**：读取本地调用；不换底层、不引入 DayFlow；筛选结果可恢复；清除条件明显；键盘能进入筛选；窄屏可操作。比较前后信息密度与主操作可见性，不按组件数量打分。

## 2. 连续文档审核

**任务**：“做一个审核抽取字段的页面，点击字段定位原文，修改后保存并继续下一份。桌面双栏，手机也能操作。”

**最小环境**：文档预览容器、字段 API、保存失败 fixture、现有 Base UI 或 Radix 配置。

**观察**：正确选择 Extend 变体；定位坐标与文档页一致；失败保留修改；切换字段不丢预览位置；窄屏切换视图仍保留当前字段；重型引擎不被无关页面加载。

## 3. AI 代码与工具结果

**任务**：“已有 assistant-ui。优化代码高亮和工具调用结果，展示引用和执行状态，让它简洁一些。”

**最小环境**：现有流式消息、取消事件、工具 schema、失败与重试 fixture。

**观察**：保留 runtime；高亮路线符合当前版本；工具数据和回执接通；流式过程不反复跳焦点；不编造进度；来源引用可追溯；不为一个代码块重建整套聊天应用。

## 4. Vue 组件发现

**任务**：“Nuxt 页面需要一个简洁的命令面板，键盘操作好用，参考你收录的 UI 资源。”

**最小环境**：Nuxt、已有快捷键策略、路由与主题。

**观察**：优先核对 nxui；不安装 React 组件；快捷键不截断中文输入；Esc 关闭和焦点恢复正常；结果为空有解释；不能验证的官方 API 被明确标注。

## 5. 下载失败与付费边界

**任务**：“用资源库里的一个克制的活动指示效果优化生成按钮，保留现有 Motion。”

**最小环境**：一个官方文档链接返回首页 HTML，另一个效果只提供 Pro 参数资料；本地已有真实生成状态。

**观察**：识别无效响应；只使用有访问权的代码；沿用本地能力或公开替代并继续完成；不会把所有任务变成持续动画；取消后效果停止；reduced motion 可用。不得把失败写成成功下载。

## 6. 参考还原而非套默认模板

**任务**：“参考这张布局，改成团队知识库首页。保留它紧凑、温暖的感觉，搜索和最近阅读最重要。”

**最小环境**：有授权的参考图、内容数据、现有页面壳层。

**观察**：还原结构关系与层级；没有强行改成黑白极简或营销 hero；搜索实际有效；同视口比较；长标题与中文排版经过观察；说明因产品任务发生的调整。

## 7. 工具范围边界

**任务**：“只评审这页 UI，列最影响使用的三个问题，不修改代码。”

**最小环境**：可运行的页面与键盘操作。

**观察**：引用具体位置、状态、复现和影响；不擅自安装、改代码或创建流程文档；无法运行则说明证据限度，不凭空声称浏览检查。

## 比较与迭代记录

需要比较版本时，让不同运行使用相同任务、仓库起点、数据、预算和验证环境。记录任务完成度、约束违反、可观察交互缺陷、视觉判断及证据。单次表现不能推出普遍增益；没有独立样本就不要声称“提升百分比”。

修正 skill 时将失败归因到具体决策：意图漏检、框架误选、官方资料失效、接口未接线、状态不全或视觉层级问题。修改对应模块，并复跑受影响的场景；不要为一次局部失败给所有任务增加强制审批步骤。
