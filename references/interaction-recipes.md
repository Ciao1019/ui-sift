# 简洁交互配方

这些是起点，不是统一模板。项目已有 token、品牌规范和用户明确要求优先。候选名称与实际导出名不一定相同，以当前组件页为准。

## 视觉与动作的分工

页面先让人认出主要内容和主要操作。使用排版、留白与对齐建立层级；边框与阴影只在需要划分容器、层级或可操作区域时加入。颜色首先表达状态，其次表达品牌。

一块工作区域通常只需要一个最强的行动入口。重要但次要的操作保持可发现，不为了“干净”全部藏进 hover 或更多菜单。数据密集的后台可以紧凑，阅读页可以舒展。

没有项目参数时可从以下范围试起，随后在真实内容里调整：

| 行为 | 参考起点 | 验收重点 |
| --- | --- | --- |
| 按钮 hover / press / focus | 约 100–180 ms，颜色或很小的位移 | 操作立即响应，焦点始终可见 |
| Tab 指示器 / 小区域切换 | 约 160–240 ms | 指向真实选中项，快速连续切换不会排队 |
| Popover / Dialog / 折叠 | 约 180–280 ms，轻微 opacity / transform | 焦点、Escape、关闭后返回触发处正确 |
| 内容插入 / 状态完成 | 一次短反馈 | 不把每行内容都逐项延迟显示 |
| 长任务 | 持续但低强度的状态提示 | 页面离开、任务完成、取消时停止 |

这些时长不是动画库配置 API。现有 CSS 能实现时不添加 Motion；已有 Motion 时不要再引入另一套运行时。长列表中避免对每一项持续运行昂贵的滤镜、阴影或布局动画。

reduced motion 下移除不必要的位移、弹性、视差与循环效果，保留静态状态差异和必要反馈。默认不自动播放音效；声音适用于用户明确选择的场景，并应有关闭方式。

## 配方 1：列表与视图切换

**任务**：快速浏览、筛选、定位一条记录。

结构用统一行高的列表或表格，标题和元数据有明确主次；搜索与当前筛选靠近结果。可查看 GodUI Segmented Control、Astryx Table、Kibo Table；层级内容查看 Kibo Tree 或 UI TripleD Nested List。

精致感来自选中项指示器、展开后的空间连续性、空结果提示和可预期的键盘行为。不要让每行同时发光、倾斜和浮起。视图导航可用 tabs；筛选选项可能更适合 radio / toggle group，语义由行为决定。

验收：长名称截断后可访问全文；重命名、删除等动作可键盘访问；筛选后给结果数；树的展开与选中不混淆；拖拽不是唯一重排方式。

## 配方 2：AI 对话与工具结果

**任务**：读懂回答，知道工具在做什么，必要时作出选择。

已有 assistant-ui 时延续它的消息与状态链；轻量新界面可考虑 prompt-kit。工具返回结构化数据交给 Tool UI 的 Citation、Data Table、Plan、Progress Tracker、Approval Card 等。对用户无帮助的调用参数默认折叠，保留状态、结果和恢复操作。

最多选一个需要强调的活动区使用 Beam / Thinking Orbs；输入框、消息、侧栏不要同时循环动画。只在真正活动时启用，并呈现文字状态。

验收：schema 校验失败有可理解的降级；流式输入不让已完成内容反复闪动；用户向上阅读时不强制滚到底；停止与重试确实接通；确认后显示操作回执；代码复制的成功与失败都有反馈。不要为展示高亮再装第二套完整 Markdown 渲染器。

## 配方 3：文档审核工作台

**任务**：在原文与抽取结果之间核对并修正字段。

桌面用“文档预览 + 字段 / 校验面板”；需要时加入页缩略图。选中字段后定位对应页和 bounding box。窄屏切为可切换的两个视图，保留当前页、字段和编辑状态。

Extend 的 Viewer、Bounding Box Citations、Layout Blocks、Schema Builder 是候选。文件选择可复用既有上传组件；除非需求确实包含编辑，不加载 DOCX / Excel Editor。

验收：引擎懒加载、失败重试、加载期间布局稳定；大文档不卡住字段编辑；低置信度有可读说明；不只用颜色表达有效性。浮层不能被预览器裁切。

## 配方 4：阅读、编辑与导图

**任务**：阅读长文或在需要时进入编辑 / 结构视图。

只读内容采用已有 Markdown 管线，缺失时评估 Lobe Markdown；编辑才用 Plate。长文用清晰标题与目录，不用很多容器打断正文。mindmapcn 用于可缩放的树状知识结构，展示优先，确需画布内编辑时再启用；为容器设置明确高度，需要时再加载。

精致感可以来自被选中文本的工具栏、定位后的轻微高亮和明确的视图转换。GodUI Highlighter 更适合少量关键引用，不能让整篇文字持续手绘动画。

验收：长代码、表格与数学内容不会撑破窄屏；编辑 / 阅读切换不丢数据；导图能回到适合视口的缩放；图形信息提供文本访问途径。

## 配方 5：日期、日程与签名

**日期范围**：开始 → 临时预览 → 确定；允许清空与重新选择，范围和时区语义清晰。普通 Calendar 足够时不引入 DayFlow。

**日程规划**：多视图、拖拽、调整时长、资源分配才使用 DayFlow 等日程库。先定义业务事件模型，明确时区、全天事件、跨日和冲突处理；核对高级能力是否需要 Pro。

**签名**：Cuicui Signature 可以提供输入参考。触摸不误触页面滚动，空签名不能提交；提供清除、重签与确认后的预览。手写画布不等同于具有法律认证的电子签署流程。

## 配方 6：落地页与精细表单

用产品的真实用途、截图、工作流或内容组织页面。Ruixen / Shadcn Studio 可提供 hero、pricing、footer 等区块；Variant 可用于探索方向。选择适合叙事的段落，不把所有营销区块都放进同一页。

moumenlab 的 File Upload Staging Area、Share & Permissions Popover、Command Palette with Argument Chips 适合改善具体流程；OTP、标签输入等先保证粘贴、IME 和键盘行为。

选择一个值得记住的细节，其余保持安静。磁吸、果冻、液态玻璃或 3D 倾斜只在品牌和任务需要时使用，普通设置表单不需要这些效果。

## 结束前的一分钟

- 是否不读说明也知道下一步？最常用动作是否容易找到？
- 去掉动画后，状态与信息仍然清楚吗？
- 真实内容变长、失败、为空时，还像同一个设计吗？
- 一个效果是否值得增加依赖、主题风险或持续渲染成本？
- 本次是否确实改善了使用过程，而不只是替换成更显眼的组件？
