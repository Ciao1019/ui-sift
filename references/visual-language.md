# 简洁界面的视觉判断

用于新页面的方向设计，或现有页面需要明显改善时。小改动沿用项目 tokens。下面的尺度是可调整的起点，不是每个页面必须使用的视觉模板。

## 1. 先决定页面的工作方式

| 工作方式 | 视觉重点 | 优先结构 | 常见误用 |
| --- | --- | --- | --- |
| 高频管理 | 扫描速度、稳定位置、快捷操作 | 紧凑列表、工具栏、详情面板 | 大卡片占满屏，操作藏得太深 |
| 深度阅读 | 行宽、段落节奏、定位 | 正文 + 可收起目录 | 多重边框、逐段入场动画打断阅读 |
| 创作编辑 | 连续输入、工具可达、选区清楚 | 内容优先、上下文工具栏 | 永久展示所有工具导致拥挤 |
| 审核判断 | 原文与结果对应、状态清晰 | 双栏对照、定位高亮 | 预览、字段、错误提示互不关联 |
| 品牌介绍 | 真实内容、记忆点、转化路径 | 与产品叙事对应的 sections | 每段套不同库的 hero 与渐变 |

## 2. 三个可独立调节的尺度

**密度**决定一屏能处理多少信息。后台不是留白越多越好；从每行内容和用户扫描方式出发。紧凑模式仍要给触摸或高频目标足够的可点区域。

**表现强度**决定视觉注意力怎样分配。默认保持低强度；品牌明确时可以增加色彩、材质或一个较强动效。主任务区域最容易识别，辅助容器退后。

**动效强度**决定状态变化如何被理解。无动效也可以优美；轻动效服务反馈，强动效需要品牌或演示理由。检索工具里的 0 / 1 / 2 只是筛选条件，不是质量评级。

不要把三个尺度绑定：一个界面可以“紧凑、低装饰、轻动效”，也可以“舒展、有品牌色、几乎静止”。

## 3. 排版承担主要层级

先确定页面标题、区域标题、正文、辅助信息、数据值的角色。角色少而明确，比为每个区块创造不同字号更稳定。

- 常规应用正文可从 14–16 px 试起，移动表单输入通常至少 16 px，仍以设备与实际阅读为准。
- 中英文混排检查中文字体回退、英文数字基线、标点挤压和按钮宽度。
- 长文从约 60–75 个拉丁字符的行宽试起；中文按实际字数与字号重新看，不直接套用英文 `ch` 值。
- 数字需要比较时可用 tabular numerals；不要把所有辅助文字都改成等宽字体。
- 不用细小淡灰字承载重要限制、价格条件或错误信息。

先用字号、字重和间距建立层级，再考虑图标和颜色。小写 / 全大写、编号、眉标只有表达实际分类或顺序时才使用。

## 4. 间距形成关系

一组内部的距离小于组与组之间的距离。表单标签与输入框靠近，错误信息属于同一字段；页面标题和全局操作属于同一区域。

若无现有规范，可从 4 / 8 / 12 / 16 / 24 / 32 的小尺度开始，按内容调整。不要机械地把所有 padding 都设为 24，也不要为了视觉对称改变语义顺序。

检查光学对齐：图标视觉中心可能不等于 SVG viewBox 中心，数字和正文也可能需要不同基线。局部微调应有原因，避免堆叠大量随意负 margin。

## 5. 颜色表达角色

优先定义语义角色：页面背景、表面、浮层、正文、次要文字、边界、主操作、成功、警告、错误、焦点。颜色值由品牌与背景决定。

同一种强调色不要同时表达“当前选中”“正在加载”“严重错误”。风险状态用图标或文字补充，不能仅靠红绿区别。

明暗模式不是简单反转颜色：暗色下边界、选中态和悬浮层需要重新观察。正文与背景、焦点与周围颜色按 WCAG 相应要求核对；透明背景先计算实际叠色，不凭色值猜对比度。

## 6. 容器与材质保持克制

只有分组、可操作对象、层级或独立状态需要容器。连续列表可用间距和轻分隔，无须每行都套卡片。

圆角、阴影与边框按层级成组复用。弹层可以有明显层级，页面内小标签通常不需要厚重阴影。玻璃效果必须检查背景内容干扰、性能和低透明度下可读性。

一个小型静态效果常常适合直接用项目原语实现。引用完整设计系统前，先问是否需要它的行为和布局能力，而不仅仅是几种颜色。

## 7. 选一个值得记住的细节

例子：文件上传时每个条目可单独取消；权限弹层返回后焦点回到原条目；视图切换保持选中记录；代码复制成功后按钮短暂变为检查标志。

这些细节来自任务。粒子、光束、果冻和视差属于另一类表达，需要更充分的场景理由。对日常工作台，流程连续性往往比持续装饰更值得投入。

## 8. 参考还原与自我评审

还原参考时在相同视口和相近内容长度下比较：大结构 → 字号与行高 → 间距 → 容器 → 色彩 → 小细节。不要用同色调掩盖结构不一致。

检查前三个视觉落点是否与任务优先级一致。移除一个装饰后若信息更清楚，保留简化；如果去掉某个分隔导致组关系不明，应保留它。审美判断应能解释对用户任务的影响。
