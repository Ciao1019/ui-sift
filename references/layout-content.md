# 布局、内容与状态压力测试

在已经确定大方向后阅读；用于把漂亮的正常态扩展为可用的真实页面。

## 页面骨架

- **后台列表**：标题与主要操作、搜索 / 筛选、结果、分页属于连续任务；筛选更新不应让焦点和滚动位置无缘无故重置。
- **详情页**：主体内容优先，元信息和辅助操作集中；返回列表保留用户之前的筛选与定位。
- **双栏审核**：两侧状态同步，明确谁滚动；窄屏切换视图时保留当前项与草稿。
- **聊天**：主消息区、输入区和辅助轨迹分工明确；长任务轨迹可折叠，未读提示不抢阅读位置。
- **设置页**：按用户理解分组，保存方式一致；局部自动保存与页面级提交不能让人猜。
- **落地页**：段落围绕产品叙事；没有可信内容时不编造客户、指标或背书。

## 响应式改变操作方式

断点按实际内容失效的位置设置，不机械照抄组件站。常用检查起点是约 390 px、768 px、1440 px，最终以目标设备与项目布局为准。

表格可采用优先列、横向滚动或专门的移动列表；不能隐藏用户必须比较的数据且不给访问入口。侧栏变抽屉时检查关闭、返回焦点、背景滚动和窄屏遮挡。

hover 中的工具按钮在触摸环境必须可发现。拖拽排序提供键盘 / 菜单替代；横向滑动组件与页面滚动不能互相劫持。底部固定输入区考虑软键盘和安全区域。

## 文案与极端内容

| 输入 | 观察什么 |
| --- | --- |
| 一个很长的中文标题 + 英文编号 | 折行、截断、可访问全文、工具栏是否被挤走 |
| URL / 文件名 / 一长串无空格字符 | 容器能否收缩，是否产生全页水平滚动 |
| 零条、1 条、几十条、很多条 | 空状态、单项对齐、分页 / 虚拟化与加载范围 |
| 数字 0、负数、较大数、缺失值 | 单位、对齐和语义；不能把缺失值当作 0 |
| 翻译后更长的按钮文案 | 字体放大和窄屏下是否仍可操作 |
| 多行错误、多个错误同时发生 | 错误能被定位，保留用户输入并给恢复动作 |

## 异步反馈

只对真正阻塞的区域显示等待，不因一个小请求把整页换成骨架。可预期布局用尺寸稳定的 skeleton；短操作可在按钮内反馈，避免闪烁式 loading。

如果进度未知，显示正在执行的阶段或不定进度。不要让 99% 停很久，也不要用定时器把失败任务演成成功。长任务明确取消、重试和后台继续的实际行为。

乐观更新必须定义失败回滚与冲突处理。Toast 不能是唯一的持久错误记录；需要用户处理的问题留在对应位置。

## 键盘、焦点与读屏

检查 Tab 顺序、焦点可见、Escape、关闭后焦点恢复、列表 / tabs 的方向键语义。中文输入法组合期间不要误把 Enter 当提交。

图标按钮有名称；label 与表单控件关联；状态变化采用合适的 live region，避免每个流式字符都播报。移除动画后仍应看出展开、选中、失败与完成。

## 性能观察

在真实操作中看输入、滚动和选区是否顺畅。高亮、富文本、PDF 和导图按需加载；长列表是否需要虚拟化由数据规模和测量决定。

不要在没有测量时给每个表达式加 memo，也不要把视觉位移问题全部归咎于动画。检查字体加载、图片尺寸、内容晚到和悬浮层定位。
